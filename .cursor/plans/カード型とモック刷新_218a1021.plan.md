# カード検索型設計の全面刷新

## 方針
- 型定義は `types/card.ts` を更新（`app/types/card.ts` への移行は行わない）。
- 「その他」カテゴリは既存の `Token` を継続利用。
- `CardDetail` は `card_category` 判別可能な Union Type へ再設計し、将来検索用の `specific` / `banilla` を型に含める。
- トークンは将来的にあらゆる分類へ拡張し得る前提で、現時点は柔軟なダミー構造（必要項目を緩めた設計）を採用する。
- `Errata` / `FAQ` は型定義とデータ保持のみ行い、`CardDetailModal` での表示実装は対象外とする。
- カード本体データは常に最新情報を保持する前提で扱う。

## 実装ステップ
1. `types/card.ts` をドキュメント準拠で再定義。
   - 共通 `BaseCard`（`id`, `name`, `card_category`, `rarity`, `element`, `type`, `product_note` など）
   - `effects` を `{ category: string; timing?: string; text: string }[]` に統一
   - カテゴリ別拡張（`UnitCard`, `SpellCard`, `ItemCard`, `RitualCard`, `LandCard`, `SummonerCard`, `TokenCard`）
   - User-Defined Type Guards（`isUnitCard`, `isSpellCard`, `isItemCard`, `isRitualCard`, `isLandCard`, `isSummonerCard`, `isTokenCard`）を同ファイルで定義
   - `Errata` / `FAQ` 型追加
   - `CardDetail` を discriminated union 化
   - `app/types/ui/search.ts` 等の検索条件型（`SearchFilter` 相当）を `land_category`, `item_category`, `move_type` など新カラムへ同期し、UIステートと型整合を確保

2. `app/utils/mockData/` を新型へ適合。
   - カード一覧・検索結果・詳細用モックをカテゴリ網羅で再構成
   - 最低1件ずつ: ユニット / 戦闘スペル / アイテム / 儀式スペル / 地形 / 召喚術師 / その他(Token)
   - 各カテゴリ固有プロパティ（例: `limit`, `land_category`, `item_category`, `is_instant_summon` など）を保持
   - 構造テストのため、カテゴリごとに一部プロパティは「あり/なし」を混在（オプショナル項目の実データ検証）
   - `Errata` / `FAQ` はモック保持まで実施し、画面描画には接続しない

3. 既存UIの型エラーを最小修正。
   - レイアウト構造（HTML/CSS）は維持
   - `CardEffect` 表示やカテゴリラベル/色マップの型不一致のみ補正

4. 検証。
   - TypeScriptエラー解消確認
   - `nuxi build` 実行でビルド通過を確認
   - 必要に応じて編集ファイルのlint診断を確認し、即修正可能なものは解消

## 完了条件
- `types/card.ts` がドキュメント記載カラムを反映し、`CardDetail` がカテゴリ判別Unionとして機能
- `types/card.ts` にカテゴリ判定Type Guard群が定義され、コンポーネント側で型安全な分岐が可能
- 検索条件型（`SearchFilter` 相当）が新カラムへ同期され、検索UIステートで型エラーが出ない
- `app/utils/mockData/` が新型準拠かつ全カテゴリサンプルを含み、オプショナル項目の有無混在を持つ
- レイアウト変更を最小限に抑えたまま型エラーが解消
- `nuxi build` が成功
