# Feature 019 数値条件の「すべて」と「なし」の検索動作

**ブランチ** `fix/numeric-presence-search-semantics`  
**作成日** 2026-11-25  
**状態** APPROVED（Spec・Plan統合Human Review）  
**関連** [Issue #34](https://github.com/Oosunakun/monsearch/issues/34) · [Plan](plan.md)

## ユーザーシナリオ

### US-1 入力を保持して条件を切り替える（P1）

詳細検索の利用者は、入力済みの数値と演算子を残したまま、画面で選んだ条件で検索したい。独立して確認するには、詳細検索でイニシアチブを操作し、検索先のURLと再表示された入力を確認する。

1. 「あり」で「2以上」を選び、「すべて」にすると数値と演算子が非表示になる。そのまま検索すると `itm` と `it` がともに省略され、イニシアチブで絞り込まない。
2. 同じ編集画面で「あり → すべて → あり」または「あり → なし → あり」と切り替えると「2以上」が再表示される。「なし」で検索すると `itm=exclude` のみを出力する。
3. 「あり」で数値を選ばず検索すると `itm=include` を出力する。「2以上」を指定すると `itm=include&it=gte:2` を出力する。

### US-2 既存リンクで検索し、結果から条件を編集する（P1）

既存リンクの利用者は、共有・保存済みのComparison単独URLから従来どおり検索し、編集画面で復元した値を再利用したい。独立して確認するには、`/cards?it=gte:2` を開いて「条件を編集」へ進む。

1. 直接開いた検索結果はイニシアチブ2以上に絞られる。編集画面では「すべて」が選択され、非表示の比較値と演算子に「2以上」が復元される。
2. 編集画面で何も変えずに検索すると、イニシアチブ条件はURLから省略される。元の結果から編集画面に入り直し、「あり」に切り替えて検索すると `itm=include&it=gte:2` が出力される。
3. `/cards?he=eq:0` の直接検索は、ユニットの英雄点0を `is_hero` にかかわらず評価する。編集時は「すべて」として復元され、「あり」を明示して再検索した場合は英雄属性も条件に加わる。

### US-3 「なし」で能力の対象カードだけを探す（P1）

利用者は、能力を持てるカードの中から、その能力を持たないカードを探したい。独立して確認するには、能力値がNULLのユニットまたは装備品と、戦闘スペル・地形を含むカード集合を検索する。

1. `itm=exclude` では通常イニシアチブを持たない対象ユニットに一致する。装備品、戦闘スペル、地形だけに由来する欠損は一致しない。
2. `aitm=exclude` では追加イニシアチブを持たない対象装備品に一致する。通常能力しか持てないユニットや、消耗品・錬金弾には一致しない。
3. ユニット詳細があるTokenでは通常側、装備品詳細があるTokenでは追加側をそれぞれ判定する。どちらの詳細もないTokenは、どちらの「なし」にも一致しない。
4. 非TokenのUnitで `unit` が欠損している場合、および非TokenのItem・Equipで `item.equip` が欠損している場合も、対応する「なし」に一致する。`item` の欠損でEquipと識別できないItemは追加能力の「なし」に一致しない。
5. 適用対象で能力行が欠損している場合は「なし」に一致する。能力値が0の場合は「あり」に一致し、「なし」から除外される。

## 機能要件

**FR-001** 詳細検索から新規生成するURLには、対象7項目ごとに以下を適用する。各行はカード分類上その項目が適用できる場合の規則とする。

| 選択状態 | Modifier | Comparison |
| --- | --- | --- |
| すべて `all` | 省略 | 省略 |
| あり `include` | 出力 | 有効な数値・演算子の組がある場合に出力 |
| なし `exclude` | 出力 | 省略 |

| 項目 | Modifier | Comparison |
| --- | --- | --- |
| イニシアチブ | `itm` | `it` |
| チャージ | `chm` | `ch` |
| ディフェンダー | `dem` | `de` |
| 追加イニシアチブ | `aitm` | `ait` |
| 追加チャージ | `achm` | `ach` |
| 追加ディフェンダー | `adem` | `ade` |
| 英雄点 | `hem` | `he` |

- **FR-002** 7項目の数値・演算子は「あり」のときに表示し、「すべて」「なし」のときに非表示にする。同じフォームでModifierやカード分類を切り替えても入力を保持する。一括クリアと選択中の数値の解除は既存操作に従う。
- **FR-003** 分類未指定とTokenでは通常・英雄点と追加の両グループを記述できる。ユニット選択時は通常・英雄点、装備品選択時は追加のみを記述できる。他の分類では両グループの保持値をURLから省略する。
- **FR-004** 受信した有効なComparison単独URLでは、7項目とも従来の比較を検索に適用する。Modifierの省略と明示の `all` は受信時に同じ意味を持つ。有効な `exclude` とComparisonの併記は復元でき、検索時はComparisonを評価対象から除く。
- **FR-005** 「条件を編集」および詳細検索URLの直接表示・再読み込みでは、有効なComparisonをModifierとは独立に復元する。Modifier省略時は「すべて」とする。再検索にはFR-001を適用し、保存してある元の検索URLは受信時の意味で引き続き検索できる。
- **FR-006** 通常・追加の6項目の `include` と `exclude` は、Query Data Specification §2.3およびHD-01に従い、能力の適用対象にだけ判定する。非Tokenの通常能力はカード分類が `Unit` であれば適用する。非Tokenの追加能力はカード分類が `Item` かつ `item_category_code === 'Equip'` の場合に適用する。`item` 自体が欠損しEquipと識別できないItemは追加能力の適用対象外とする。Tokenは通常能力では `unit`、追加能力では `item.equip` が存在する場合に適用する。
- **FR-007** 適用対象の「あり」は0を含む数値の存在を条件とし、有効なComparisonの併記時は両方の条件を評価する。「なし」は、適用対象で対応詳細、能力行、対象値のいずれかが欠損している場合や、値がNULLの場合に一致する。非TokenのUnitで `unit` / `unit.ability` が欠損する場合、非TokenのItem・Equipで `item.equip` が欠損する場合も該当する。戦闘スペル・地形など適用対象外のカードは「あり」「なし」のいずれにも一致しない。NULLを0へ変換せず、Comparison単独ではNULLに一致しない。
- **FR-008** 英雄点の `include` / `exclude` はユニットの `is_hero` を参照する。`include` はComparisonを併記でき、`exclude` はComparisonを評価しない。Comparison単独の受信を `include` と読み替えない。
- **FR-009** `lvm` の即時召喚属性と `lv` のレベル比較は独立に生成・評価する。レベルの入力はModifierに関わらず表示し、`lvm=exclude&lv=gte:2` は両条件を評価する。所持枠の `none` も従来の対象および判定規則に従う。
- **FR-010** 同一カード集合と条件に対し、ブラウザ検索と `GET /api/cards` は同じ一致集合と件数を返す。既存の並び順・集計・ページ制御にはその一致集合を渡す。

## 境界ケースと互換性

- 有効な0、正数、負数を比較できる。未指定・不正な比較値はURL生成で省略し、`include` 単独は成立する。受信時のAlias、検証、重複、未知値、エンコードの既存規則を継続する。
- 受信値が既存UIの数値ボタンにない場合も既存Parserの受理範囲で復元・保持する。ボタンの選択肢は既存の範囲を使用する。
- 既存の `exclude&Comparison` は直接受信して検索できる。対象外カードの除外は意図した検索結果の変更である。`include&Comparison` は適用対象で比較を続ける。
- 分類と能力を併記した受信URLは両条件を適用する。新規生成時の分類による省略規則はFR-003に従う。
- 非表示値を保持する範囲は同じ編集フォームとする。再検索後のURLに出力されなかった値は、そのURLを新たに開いたフォームの復元対象に含まれない。

## 成功基準

- **SC-001** 7項目すべてで「すべて」「あり・数値なし」「あり・数値あり」「なし」が期待するURLを生成し、同一フォームで「あり」に戻すと保持した数値・演算子を使える。
- **SC-002** イニシアチブと英雄点を含むComparison単独URLで、直接検索・条件編集・無変更再検索・「あり」へ変更後の再検索の4段階が期待どおりに動く。
- **SC-003** 通常・追加の全6項目で、適用対象と対象外、および欠損・NULL・0の代表カードの期待ID集合が一致する。Token、英雄点、即時召喚、レベル、所持枠の回帰例も期待どおりに動く。
- **SC-004** 同一入力で行うブラウザ検索とAPIの代表シナリオすべてで、一致ID・件数・分類集計が一致する。

## Human Decision

**HD-01（A案、APPROVED）** 非TokenはUnitまたはItem・Equipと識別できれば、対応詳細が欠損していても適用対象とする。Tokenは対応詳細の存在で判定する。分類・詳細欠損ごとの確定要件はFR-006・FR-007に記載した。未決のHuman Decisionはない。
