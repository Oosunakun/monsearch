# Feature Specification: 検索条件編集

**Feature Branch**: `feature/search-condition-edit`

**Created**: 2026-08-29

**Status**: Draft

**Input**: User description: "search-condition-edit"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 現在の検索条件を引き継いで編集する (Priority: P1)

カード検索の利用者として、検索結果画面から詳細検索画面を開いたときに、現在の検索条件が入力済みであってほしい。これにより、条件を一から入力し直さずに検索を調整できる。

**Why this priority**: 現在の条件を失わずに編集を開始できることが、この機能の中心的な利用価値であるため。

**Independent Test**: テキスト、複数選択、数値比較を含む検索結果から「条件を編集」を選択し、詳細検索画面の各対応項目に同じ意味の条件が表示されることを確認することで、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 有効な検索条件を含む検索結果画面を表示している、**When** 利用者が「条件を編集」を選択する、**Then** 詳細検索画面が開き、現在の有効な検索条件が対応する入力項目へ復元される。
2. **Given** 条件を指定していない検索結果画面を表示している、**When** 利用者が「条件を編集」を選択する、**Then** すべての項目が既定値の詳細検索画面が開く。
3. **Given** 共有またはブックマークした検索結果を開いている、**When** 利用者が「条件を編集」を選択する、**Then** その場所に表現された検索条件が詳細検索画面へ復元される。

---

### User Story 2 - 条件を変更して再検索する (Priority: P2)

カード検索の利用者として、引き継がれた条件を追加、変更、または解除して再検索したい。これにより、結果を確認しながら段階的に目的のカードへ絞り込める。

**Why this priority**: 条件の復元後に調整して再検索できることで、編集操作が一連の検索体験として完結するため。

**Independent Test**: 復元された条件の一つを変更し、別の条件を解除して検索を実行し、変更後の全条件だけが検索結果に反映されることを確認することで検証できる。

**Acceptance Scenarios**:

1. **Given** 現在の検索条件が詳細検索画面へ復元されている、**When** 利用者が条件を変更して検索する、**Then** 変更後の全条件を表す検索結果画面が表示される。
2. **Given** 現在の検索条件が詳細検索画面へ復元されている、**When** 利用者が条件を解除して検索する、**Then** 解除した条件を含まない検索結果画面が表示される。
3. **Given** 現在の検索条件が詳細検索画面へ復元されている、**When** 利用者が変更せずに検索する、**Then** 元と同じ意味の検索条件で結果画面が表示される。

---

### User Story 3 - 不正な条件があっても安全に編集を続ける (Priority: P3)

カード検索の利用者として、古い共有リンクや手作業で変更された場所に認識できない条件が含まれていても、認識できる条件を使って編集を続けたい。これにより、一部の不正な値によって検索全体をやり直さずに済む。

**Why this priority**: 共有リンクや将来の条件変更に対して編集導線を壊れにくくし、利用者が回復できるようにするため。

**Independent Test**: 有効な条件と未知、不正、または不完全な条件を混在させた検索結果から編集画面を開き、有効な条件だけが復元され、編集と再検索を完了できることを確認することで検証できる。

**Acceptance Scenarios**:

1. **Given** 有効な条件と認識できない条件が混在する検索結果画面を表示している、**When** 利用者が「条件を編集」を選択する、**Then** 認識できる有効な条件だけが復元され、画面を操作できる。
2. **Given** 値が不完全な条件を含む検索結果画面を表示している、**When** 利用者が「条件を編集」を選択する、**Then** その条件は安全な既定値として扱われ、ほかの有効な条件は保持される。

### Edge Cases

- 同じ条件が複数の表現で含まれる場合でも、既存の検索条件解釈規則に従った一つの編集状態になる。
- 日本語、空白、予約記号、絵文字を含むテキスト条件は、意味を変えずに入力項目へ復元される。
- 数値のゼロなど有効な境界値は、未入力として失われない。
- 選択したカードカテゴリに適用されない保持済み条件は、再検索へ混入しない。
- 編集画面を直接開き、引き継ぐ条件がない場合は、すべての項目が既定値になる。
- 認識できる条件が一つもない場合でも、利用者は既定状態のフォームから編集を続けられる。
- 編集画面を再読み込みしても、その場所に表現された条件から同じ編集状態を復元できる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 検索結果画面は、現在の検索条件を保持したまま詳細検索画面へ移動できなければならない。
- **FR-002**: 詳細検索画面は、受け取った現在の検索条件を、対応するすべての編集可能な項目へ復元しなければならない。
- **FR-003**: 復元対象は、既存の詳細検索フォームが扱うテキスト、単一選択、複数選択、数値比較、絞り込み方法、および論理一致条件を含まなければならない。
- **FR-004**: 引き継ぐ検索条件がない状態で詳細検索画面を開いた場合、すべての項目を既定値で表示しなければならない。
- **FR-005**: 利用者は、復元された条件を追加、変更、および解除できなければならない。
- **FR-006**: 編集後に検索を実行した場合、編集時点で有効な条件だけを使った検索結果を表示しなければならない。
- **FR-007**: 条件を変更せずに再検索した場合、元と同じ意味の検索条件を再現しなければならない。
- **FR-008**: 日本語、空白、予約記号、絵文字、および有効な数値境界を含む条件は、結果画面から編集、再検索まで意味を保持しなければならない。
- **FR-009**: 未知、不正、または不完全な条件は、ほかの有効な条件の復元、編集、および再検索を妨げてはならない。
- **FR-010**: 未知、不正、または不完全な条件を、有効な別の条件として編集項目へ表示してはならない。
- **FR-011**: 選択したカードカテゴリに適用されない保持済み条件を、再検索の条件へ含めてはならない。
- **FR-012**: 編集画面の再読み込み時にも、その場所に表現された条件から同じ意味の編集状態を復元しなければならない。
- **FR-013**: この機能は、既存の検索条件の意味および検索実行時の判定規則を変更してはならない。

### Key Entities

- **現在の検索条件**: 表示中の検索結果を導いた、利用者にとって意味のある有効な条件の集合。
- **編集状態**: 現在の検索条件を各入力項目、選択、比較方法、および一致方法として表した状態。
- **検索条件編集画面**: 現在の条件を確認し、追加、変更、解除して再検索するための詳細検索画面。
- **検索結果の場所**: 共有や再読み込みが可能で、現在の検索条件を表す検索結果画面の場所。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 既存の詳細検索項目を網羅する代表ケースで、有効な条件の100%が結果画面から対応する編集項目へ同じ意味で復元される。
- **SC-002**: 条件を変更しない結果、編集、再検索の往復テスト100件で、100%が元と同じ意味の検索条件になる。
- **SC-003**: 通常の利用環境で、「条件を編集」を選択してから入力済みフォームを操作可能になるまでが、測定の95%以上で1秒以内である。
- **SC-004**: ユーザビリティ確認の参加者の90%以上が、説明なしで結果画面から一つの条件を変更し、一回の試行で再検索を完了できる。
- **SC-005**: 有効な条件と不正な条件を混在させた代表ケースの100%で、有効な条件を失わずに編集と再検索を完了できる。

## Assumptions

- 「search-condition-edit」は、カード検索結果画面の「条件を編集」から既存の詳細検索画面へ戻り、現在の条件を編集する機能を指す。
- 現在の検索条件は検索結果の場所に表現されており、既存の承認済み検索条件解釈規則で詳細検索フォームへ復元できる。
- 条件の解釈、既定値、正規化、およびカードカテゴリへの適用可否は、既存の検索仕様に従う。
- 新しい検索項目、検索エンジンの変更、条件の永続保存、検索履歴、および利用者アカウントとの同期は対象外とする。
- 編集の取り消し専用操作や未確定変更の破棄確認は対象外とし、通常の画面移動の挙動に従う。
