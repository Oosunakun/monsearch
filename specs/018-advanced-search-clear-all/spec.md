# Feature Specification — 詳細検索の条件を一括クリア

- Feature 018
- 作業ブランチ `feature/advanced-search-clear-all`
- Spec・Plan統合Human Review **APPROVED**（`minimal-review`）。実装後のHuman ReviewでHD-02の最終デザインも確定
- [Issue #33](https://github.com/Oosunakun/monsearch/issues/33) · [Plan](plan.md) · [Tasks](tasks.md)

## ユーザーシナリオと受入条件

### US1 — 一度の操作で条件を入れ直せる（P1）

詳細検索の利用者として、複数の条件を指定したあと、一項目ずつ解除する手間をかけずに最初から条件を組み直したい。

1. テキスト、分類、複数選択、数値条件、所持枠などを設定し、「すべての条件をクリア」を一度操作すると、確認ダイアログを挟まず、詳細検索の全項目が既定値に戻る。
2. ユニット・装備品・地形の条件を設定し、分類を選んで一部の条件を隠してからクリアすると、分類の選択も解除される。再表示された項目には以前の値が現れない。
3. 存在条件の指定によって数値欄が隠れている場合や、所持枠を「なし」にして枠の内訳が隠れている場合も、再び入力欄を表示すると、旧値や旧演算子・旧個数は復活しない。

### US2 — クリア後に検索するかを自分で選べる（P1）

検索結果から条件を編集している利用者として、詳細検索の入力だけを消し、その後に検索するか、元のURLの条件に戻るかを選びたい。

1. URLから詳細検索の条件を復元し、簡易検索にも入力・検索対象の選択がある状態でクリアすると、詳細検索だけが初期化される。簡易検索の入力値と検索対象、現在のURL、ブラウザー履歴は維持され、検索は発生しない。
2. クリア後に他の条件を入力せず「この条件で検索」を押すと、条件なしの結果画面が開く。条件を入れ直した場合は、入れ直した条件だけで検索される。
3. クリア後、検索せずに詳細検索画面を再読み込みすると、そのURLに含まれる有効な条件が元どおりに表示される。

### US3 — PC・スマートフォン・キーボードで操作できる（P1）

詳細検索の利用者として、画面幅や入力方法にかかわらず、検索とクリアを見分けて実行したい。

1. PC・モバイルとも、左に「この条件で検索」、右にクリアボタンが横一列に並ぶ。クリアボタンの表示はPCで「すべての条件をクリア」、モバイルで「クリア」。約320 CSS pxのモバイル画面でもボタンが欠けず、操作領域に起因する横スクロールがなく、両方を押し分けられる。画面下部の操作領域は現行の検索ボタン一列分を基準とし、最下部の入力欄を表示・操作できる。
2. PC・モバイルとも、Tabで検索からクリアへ移動でき、フォーカスが見える。クリアボタンのアクセシブルネームは両方で「すべての条件をクリア」。EnterまたはSpaceはフォーカス中のボタンだけを実行する。既存の検索対応入力欄でのEnter操作も引き続き利用できる。

### 境界ケース

- すでに既定値のフォームでもクリアを操作できる。連続してクリアした場合も、表示は既定値のままで検索や遷移は起きない。
- 画面を開いた直後にURLからの条件復元が保留されていても、受け付けたクリア操作が遅れて届いた復元で取り消されることはない。その後の再読み込みでは通常どおりURLから復元される。
- 条件を持たないURLを開き直すと既定値が表示される。未知・無効なURL条件が混在する場合は、従来どおり有効な条件だけが復元される。

## 要件

### 機能要件

- **FR-001** PC・モバイルとも、同じ操作領域で検索を左、クリアを右に横一列で表示する。検索ボタンのラベルとデザインは現行のままとし、クリアボタンの表示テキストはPCで「すべての条件をクリア」、モバイルで「クリア」とする。
- **FR-002** クリアは一度の操作で実行し、確認ダイアログを表示しない。テキスト、分類、単一・複数選択、種族・タイプを含む詳細検索の全項目を初期状態に戻す。
- **FR-003** 分類や絞り込み状態で隠れている値もクリアする。数値条件のModifier・比較演算子・数値、所持枠・効果コストの内訳と個数・論理一致方法も、項目ごとの既定値に戻す。
- **FR-004** クリアはヘッダーまたはスマートフォンのドロワーの簡易検索入力・検索対象に影響しない。クリアだけで検索、URL変更、ブラウザー履歴の追加・置換は行わない。
- **FR-005** クリア後に明示的に検索した場合は、その時点の詳細検索条件を使用する。クリア直後の既定値で検索すると条件なしの結果を開く。
- **FR-006** クリア後に検索せず再読み込みした場合は、そのURLの有効な条件を通常どおり復元する。同じページ表示中の、クリアより遅れて完了する初期復元はクリアを取り消さない。
- **FR-007** 約320 CSS pxのモバイル画面でもボタンの欠けや操作領域に起因する横スクロールがなく、両ボタンのタップ領域と押し分けやすさを確保する。画面下部の操作領域は現行の約2倍の高さを占有せず、最下部の入力欄を表示・操作できること。DOM順・視覚順・Tab順は検索→クリアとし、クリアのアクセシブルネームはPC・モバイルとも「すべての条件をクリア」とする。フォーカスを視認でき、Enter・Spaceで対象ボタンだけを実行できること。

### 対象となる状態

- 詳細検索の入力中の条件は、現在のページ上で編集する値。画面に表示されていない条件も含む。
- 現在のURLの条件は、ページを開き直したときの復元元。
- 簡易検索の入力・検索対象は、詳細検索とは独立して編集する値。

## 成功基準

- **SC-001** 一度のクリアで、全7セクションのフォーム状態が新規表示時の既定値と一致する。分類を戻したり、数値・枠の入力欄を再表示したりしても、以前の条件が残っている項目は0件。
- **SC-002** クリア前後で簡易検索の入力と選択が一致し、クリアに起因する検索・URL変更・履歴操作がそれぞれ0回。検索を明示的に選んだときだけ、その時点の条件で検索できる。
- **SC-003** 条件付きURLで、同じ表示中はクリア済みの条件を保ち、クリア後の再読み込みではURLの有効な条件を復元できる。
- **SC-004** PCと幅320 CSS pxのモバイル画面で、検索は左、クリアは右に一列で表示される。画面幅に応じたクリアの表示テキストと共通のアクセシブルネームを確認できる。ボタンの欠けや横スクロールがなく、モバイルの操作領域は現行の一列分に近い高さで、両ボタンを個別にタップでき、最下部の入力欄にもアクセスできる。キーボードでは検索→クリアの順にフォーカスし、それぞれ独立して実行できる。

## 前提・対象外

- 各項目の既定値、検索条件の意味、URL Query仕様、検索結果の判定は既存仕様に従う。
- 簡易検索のクリア、検索結果画面へのクリア操作の追加、クリアの永続化や取り消し機能、折りたたみ状態や選択ダイアログ内の候補絞り込み文字列の初期化は対象外。

## 承認済みのHuman Decision

- **HD-01 配置** — PC・モバイルとも横一列とし、左に検索、右にクリアを置く。DOM順・視覚順・Tab順は検索→クリアで揃える。
- **HD-02 デザイン** — 既存の検索ボタンのデザインを維持する。クリアは `variant="outlined"`、背景色 `#f2f7fb`、文字色 `#386b8a`、枠線 `1px solid #b6cddc`、文字ウェイト `font-weight-medium` とする。配色は `.search-actions-clear-theme`、モバイルの寸法は `.search-actions-clear` に定義する。表示テキストはPCで「すべての条件をクリア」、モバイルで「クリア」とし、アクセシブルネームは共通で「すべての条件をクリア」とする。
