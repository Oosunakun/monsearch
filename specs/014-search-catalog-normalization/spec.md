## ユーザーシナリオとテスト

### ユーザーストーリー1 - catalogによるキーワード検索（優先度: P1）

利用者は文字幅や英字大小の違いを気にせず、検索専用catalogに登録された内容でカードを探せる。

**優先理由**: 正しい検索対象への切替と、毎回カード全文を加工する負荷の解消が中心目的である。

**独立テスト**: catalogだけにある語、表示原文だけにある語、文字幅が異なる語で独立した固定期待カードID集合を確認する。

**受入シナリオ**:

1. catalogにm20a-001があるとき、Ｍ２０Ａ－００１とm20a-001で同じカードID集合を得る。
2. catalogにスペル:*、攻撃力:+2、リブ&ラブ、アーニャがあるとき、全角記号・半角カナ等の対応入力でも同じ集合を得る。
3. catalogだけにある語は一致し、表示原文だけにある語は一致しない。
4. 対象値が欠損・null・空文字なら、非空検索語に一致せず、別項目で補わない。

### ユーザーストーリー2 - archetype専用値による検索（優先度: P2）

利用者は種族・カード種別の表示情報から検索時に組み立てた値ではなく、受領済みarchetype専用値に登録された語でカードを探せる。

**優先理由**: 提供済みの専用値を使い、attの検索対象の不一致を解消する。

**独立テスト**: 正規化済みcatalogだけにある語と表示種族だけにある語を固定fixtureで区別する。

**受入シナリオ**:

1. archetype専用値だけにある語がattに一致し、英字大小・文字幅はkwと同じN₀で扱う。
2. 語が表示種族・カード種別だけにある場合、または専用値が欠損・null・空文字の場合は一致しない。
3. kwとattの併用では、両方を満たすカードだけが残る。

### ユーザーストーリー3 - 原文と既存検索を保って負荷を軽減する（優先度: P2）

利用者は既存の入力・共有URL・表示原文を保ったまま検索できる。検索対象全文の繰返し生成・正規化と、カードごとの検索語変換をなくす。

**独立テスト**: Repository内のUnit Test・API Testで、既存回帰と変換の呼出構造を確認する。

**受入シナリオ**:

1. 照合用N₀が入力・URL・表示原文へ反映されず、既存の前後trimは維持される。
2. catalog条件なしのnm / rl / etxや他条件で、結果・分類・件数・順序・ページ・応答項目が事前baselineと一致する。
3. catalogと他条件のAND、is_tokenによる既存Token分類、sort・pagination・集計を維持する。
4. 一回のAPI / searchCardsのカード走査前に、有効なkw・att各検索語を一度だけ変換する。走査中の対象全文生成・再正規化・検索語再変換は行わない。

### 境界ケース

- 未指定または既存Parser後に空となるkw・attは条件なし。
- 内部の連続空白・改行・タブを保持し、検索語全体を単一のliteralとして扱う。
- ①≠1、Ⅰ≠I、あ≠ア、〜≠～、ー≠-、‐≠-、−≠-を維持する。
- ｶﾞはカ＋U+3099、ﾊﾟはハ＋U+309Aとなり、合成済みのガ・パと区別する。
- 正規化されていないcatalogの境界fixtureも再正規化・補修しない。表示原文へ戻さない。

## 要件

### 機能要件

- **FR-001**: kwはcards.jsonのsearch_support.full_textだけを対象とし、表示情報連結・カード全体の文字列化による代用を廃止する。
- **FR-002**: attはcards.jsonのsearch_support.archetype_textだけを対象とし、種族・カード種別連結による代用を廃止する。両専用値は受領済みのN₀正規化済み文字列として扱う。
- **FR-003**: N₀は全角ASCII U+FF01〜U+FF5Eを対応ASCIIへ、U+3000をASCII空白へ、U+FF61〜U+FF9FをQDS対応先へ変換し、幅変換後のASCII A〜Zだけをa〜zへ揃える。U+FFE0〜U+FFE6は順に¢ / £ / ¬ / ¯ / ¦ / ¥ / ₩、U+FFE8〜U+FFEEは順に│ / ← / ↑ / → / ↓ / ■ / ○へ変換する。結果を追加で互換分解しない。
- **FR-004**: N₀はカナ合成、全体NFC / NFKC、非ASCII小文字化、ひらがな／カタカナ変換、同義語・誤字補正を行わない。内部空白・改行・タブを削除・圧縮・置換せず、再適用しても不変とする。
- **FR-005**: 対象catalogは提供時点でN₀適用済みであることを前提とする。リクエスト時にkw・attの対象全文を生成・再正規化しない。
- **FR-006**: 変換後の検索語全体でliteral部分一致する。単語分割・正規表現・wildcard解釈をせず、空条件はskip。非空条件に対する対象欠損・null・空文字は非ヒットで、補修・fallbackをしない。
- **FR-007**: カード原文、表示値、入力値、URLの文字表現をN₀で書き換えない。既存URL生成・解析・前後trimを維持する。
- **FR-008**: nm / rlの既存小文字化照合、etxの既存normalizeQdsText・効果本文検索・同一Effect条件を維持する。effect_nameの独立条件を追加しない。
- **FR-009**: 他条件とのAND、カード単位判定、search_support.is_tokenと既存Token分類、表示項目、件数・categoryBreakdown・sort・pagination・API契約を維持する。catalog切替の結果差は新対象に対する固定期待ID集合で検証する。
- **FR-010**: Repository内の固定テストベクトルと受領JSONを用い、N₀の仕様一致・冪等性・両専用値の入力契約を確認する。期待値・期待ID集合は本番normalizer / matcherから逆算しない。提供工程の検証は要求しない。
- **FR-011**: APIとsearchCardsでは、有効なkw・att各検索語へN₀をカード走査前に一度だけ適用する。predicate実行中に検索語を再変換せず、この構造を自動テストで確認する。
- **FR-012**: 正式QDSに対する対象の事前正規化・カナ合成省略の暫定例外と、nm / rlの既存未対応を明記する。正式QDSやDecision履歴を上書きしない。

### 主要エンティティ

- **入力catalog**: cards.jsonのカードに属するfull_text・archetype_text。表示原文と独立したN₀正規化済み文字列。
- **N₀**: 指定された文字対応だけを行う照合用純粋変換。
- **catalog検索条件**: 元のSearchForm表現と、走査前に準備したkw・att照合値。
- **受入記録**: Repository入力の確認、自動テスト結果、固定期待ID集合、既存失敗と新規差分。

## 成功基準

- **SC-001**: 指定幅対応172文字とASCII大文字26文字、代表・境界vectorが固定期待値と100%一致する。vectorでN₀(N₀(x)) = N₀(x)、受領catalogでN₀(value) = valueが成立する。
- **SC-002**: kw・att・併用の固定期待カードID集合と100%一致する。欠測・literal・非同一視に意図しない一致がない。
- **SC-003**: catalog切替に由来しない既存検索・Token分類・レスポンス・入力・URL・表示原文の新規差分がない。既存失敗は事前baselineと分けて記録する。
- **SC-004**: API / searchCardsの各走査で、有効な各catalog検索語のN₀呼出は走査前の1回のみ。対象全文生成・対象再正規化・走査中のquery再変換は0回であることを自動検証する。

## 前提・範囲・Review Gate

- cards.jsonは入力の正本。現行482件の両専用値は受領済みで、存在・string型・N₀固定点の事前検証はPASSしている。実装・Unit/API Testの成功とは区別する。
- 正常入力のcatalogはN₀済みstring。nullable / optionalは欠測の照合境界を表すために型・fixtureで扱い、正常入力の契約を緩めない。
- 旧連結検索の全結果との一致は要求しない。新対象の期待ID集合と、catalog条件なしの回帰を分離する。
- 入力提供工程の内部構造・管理・実装・履歴の確認は依存条件にしない。新たな永続モデル・検索基盤は追加しない。
- nm / rlのQDS完全準拠化、etx変更、is_token変更、未対応文字の拡張、他の性能最適化は対象外。
- CPU反復測定・中央値改善、実機測定、ブラウザー表示速度、人間による実動作確認は必須完了条件ではない。未実施を実施済みとせず、未実施だけをImplementation未完了の理由にしない。
- 性能改善はFR-005/011・SC-004の構造要件として維持する。実行環境の性能適合や公開可否の保証は本Featureの完了判定に含めない。
- **仕様・PlanのHuman Review承認前に実装しない。承認後は承認された範囲で実装・検証を進める。**
